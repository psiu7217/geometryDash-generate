# Справочник объектов Geometry Dash 2.2 / 2.209+ для генератора

> Сначала читать [AGENTS.md](../AGENTS.md). Этот документ — **каталог семейств и подтверждённых примеров ID**, а не список всех 4539 номеров подряд. По игре 2.2 известны пропуски, скрытые, устаревшие, неоднозначные и неиспользуемые ID. Полную внешнюю таблицу «ID ↔ имя спрайта» см. ниже. Статус наличия ID в GD **не означает поддержку `gdgen`**.

## 1. Где искать все доступные ID

- **Большой индекс 2.2:** [frqubit — GD2.2 Object IDs to plist file names](https://gist.github.com/frqubit/39bf5e3c6a072096424d93055991d7f8) — соответствие номера и имени ресурса из EXE 2.2; искать по имени спрайта или ID. В нём тысячи позиций, но название ресурса **не гарантирует назначение, наличие в палитре редактора и корректную хитбокс-модель**. Для 2.209 перепроверять.
- **История ID, скрытые и удалённые объекты:** [Library of Geometria — Object IDs](https://a-zalt.github.io/gdknowledge/resources/object_ids.html). Максимальный исторический номер не равен числу доступных предметов.
- **Категории редактора:** [Official Geometry Dash Wiki — Level Editor](https://geometrydash.wiki.gg/wiki/Level_Editor) и [Update 2.2](https://geometrydash.wiki.gg/wiki/Update_2.2).
- **Машиночитаемая структура объекта:** [GD Docs — Level String](https://boomlings.dev/resources/client/level-components/level-string), [формат проекта](FORMAT.md).
- **Свойства, хитбоксы, точный смысл специальных объектов:** сверять с экспортом **маленького тестового уровня из текущей GD**, а не угадывать по спрайту.

**Метод для агента:** найти объект в источнике -> подтвердить ID и интерактивность -> проверить свойства из экспортированного `k4` -> добавить маленький воспроизводимый пример -> проверить поведение -> только потом включать в игровой генератор.

## 2. Категории объектов и конкретные ID

Отметки: **ENGINE** = высокоуровневый генератор уже строит такую механику; **RAW** = базовый сериализатор `GDObject` умеет записать ID/props, но поведение не моделируется; **CHECK** = требуется проверка в GD 2.209+ перед использованием.

### Твёрдые поверхности, платформы, склоны и шипы

| ID / семейство | Что даёт в игре | Статус здесь |
| --- | --- | --- |
| `1` | стандартный solid block | ENGINE |
| `2–7`, `83`, `502` | другие варианты базовых квадратных блоков; внешний вид различается | RAW, CHECK |
| `1903` | plank / платформа | RAW, CHECK |
| `1910`, `1911` | маленькие block и plank | RAW, CHECK |
| `8`, `39`, `103` | шипы разных размеров/форм | `8` ENGINE, остальные RAW |
| `144`, `145`, `205`, `459` | невидимые шипы — **не использовать для облегчённых уровней** | RAW, CHECK |
| `216–218`, `458` | цветные варианты шипов | RAW, CHECK |
| `85–87`, `97` | вращающиеся зубчатые элементы (семейство cogwheel) | RAW, CHECK |
| `1705–1707` | варианты sawblade | RAW, CHECK |
| `177–179` | ice spikes | RAW, CHECK |
| `1889–1891`, `393` | fake spikes (декоративные, но сверять hitbox) | RAW, CHECK |
| различные `triangle_*`, `block*_slope_*`, `plank*` | наклонные поверхности, углы, соединения, склоны, рамки, заливки | RAW, CHECK |

Не выводить коллизию по графике. Скат/слоуп, mini-block, разрушаемый или невидимый объект могут иметь иную физику. Для любых семейства slopes/force/solid, кроме `1`, нужен тест хитбокса.

### Порталы режимов, скорости, размера и гравитации

| ID | Назначение | Статус |
| --- | --- | --- |
| `12`, `13` | Cube / Ship | ENGINE |
| `47`, `111` | Ball / UFO | порталы доступны в ENGINE, но **геометрия режима не реализована** |
| `660` | Wave | ENGINE (пока упрощённый Ship-подобный коридор) |
| `745`, `1331`, `1933` | Robot / Spider / Swing | RAW, нет собственной физики |
| `10`, `11` | normal / reversed gravity | RAW |
| `99`, `101` | normal / mini size | RAW |
| `45`, `46` | Mirror on/off (legacy) | RAW, CHECK |
| `286`, `287` | dual on/off portals | RAW, CHECK |
| `200`, `201`, `202`, `203`, `1334` | Slow, Normal, Fast, Faster, Fastest | ENGINE (разделение секций) |

**Важно:** текущий `gdgen/generator.py` создаёт портал очередного режима на границе секций, но **не гарантирует его пересечения реальным игроком**, а старт всегда Cube. Прежде чем считать `ball`, `ufo`, `robot`, `spider`, `swing` поддержанными, нужны отдельные генератор и тесты.

Для **декоративной** геометрии использовать визуальные ID, которые реально не имеют твёрдого hitbox. Не подменять их `id=1` в игровом пространстве. Выбор `Editor Layer=3` (поле `20`) **не делает** объект фоновым; Z Layer задаётся полем `24`, Z Order — `25`.

## 3. Что ещё может делать редактор GD 2.2

Объекты можно размещать с произвольными координатами/поворотом, отражать, масштабировать по X/Y, перекрашивать двумя каналами, изменять HSV, группировать, выбирать editor layer, Z layer/order, режимы Fade/Enter, блокировать коллизию у специальных объектов, привязывать к триггерам; поддерживаются специальные фоны, grounds и middleground, анимированные объекты, текст, particle editor и пиксель-арт.

Отдельная категория — **триггеры**: перемещение, поворот, масштаб, альфа, пульсация, анимации, группы, условная логика, камера, шейдеры, музыка, SFX, time/item variables, area/enter-эффекты, смена геймплея. См. [TRIGGER_CATALOG.md](TRIGGER_CATALOG.md). Записать ID как число недостаточно: большинство триггеров требует свойств и целевых Group/Item/Color ID.

## 4. Базовые свойства объектов (для `GDObject.props`)

| Ключ | Назначение | Замечания |
| --- | --- | --- |
| `1,2,3` | object ID, X, Y | сериализатор `GDObject` формирует эти ключи автоматически |
| `4,5` | flip X / flip Y | bool 0/1 |
| `6` | rotation (°) | величина влияет и на вид, и на хитбокс при некоторых объектах |
| `20`, `61` | editor layer 1 / editor layer 2 | **не** порядок рисования |
| `21`, `22` | main / secondary Color ID | канал должен существовать в level colors |
| `24`, `25` | Z Layer / Z Order | порядок отрисовки, отличен от Editor Layer |
| `31` | base64-текст для текстового объекта | не писать произвольный UTF-8 без кодирования |
| `32`, `128`, `129` | scale, scale X, scale Y | 2.2 имеет non-uniform scale |
| `57` | групповые ID | разделитель `.`, например `100.101`; не путать с target group триггера |
| `34` | Group Parent | влияет на операции вращения/масштаба группы |
| `41–44` | HSV-флаги и значения основного/доп. цветов | нужен формат HSV |
| `64`, `67`, `103` | Don't Fade, Don't Enter, High Detail | некоторые параметры применимы лишь к определённым типам |

Весь список специальных полей (триггеры и новые поля 2.2) берётся из [GD Docs — level-string](https://boomlings.dev/resources/client/level-components/level-string). Нельзя применять свойство к чужому типу объекта, если семантика не подтверждена.

## 5. Пример низкоуровневого использования

```python
from gdgen.objects import GDObject

# Визуальный объект с цветом, группой и отдельным Z-порядком.
decor = GDObject(
    id=48, x=450, y=300,
    props={21: 2, 57: "101", 20: 3, 24: 1, 25: -2, 32: 1.25},
)

# Твёрдый блок — не использовать в проходе как «фон».
solid = GDObject(id=1, x=600, y=15, props={21: 2})
```

Низкоуровневый объект можно добавить в `Level.objects`; `Level.to_level_string()` включит его в файл. Но **визуализация и валидация новых типов в проекте от этого автоматически не появятся**.

## 6. Контроль качества

1. Фиксировать каждый внедрённый ID в тесте: serialize -> load .gdlvl -> object props.
2. Указывать *игровой риск* — `collision`, `portal`, `trigger`, `cosmetic`, `unknown`. Не предполагать «cosmetic» по одному имени файла.
3. Для новых типов обновить preview и validator или явно предупреждать, что их пока не видно/не проверяют.
4. Проверять минимум один импорт в редактор и, для игровых объектов, отдельный playtest.
5. Не включать диапазоны ID «подряд»: среди них есть пропуски, старые объекты и нестандартные ресурсы.

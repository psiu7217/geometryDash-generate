# Справочник триггеров Geometry Dash 2.2 / 2.209+ для ИИ-агента

> Читать вместе с [AGENTS.md](../AGENTS.md) и [OBJECT_CATALOG.md](OBJECT_CATALOG.md). **Список описывает возможности игры, а не обещает, что генератор их реализует.** Сегодня `gdgen` программно создаёт **Color Trigger (899)** в общем генераторе и **Color/Pulse/Alpha/Move (899/1006/1007/901)** для чисто декоративных групп пресета Moonlit Cloud Kingdom. Статический валидатор проверяет существование целевых Group ID и Color ID, но не доказывает действие триггеров в игре. Остальные триггеры можно представить через `GDObject(id,x,y,props)`, однако для их правильной настройки нужны типизированная модель и игровые тесты.

## 1. Полные источники и правила точности

- [Official Geometry Dash Wiki — Triggers](https://geometrydash.wiki.gg/wiki/Triggers) — обширный перечень (wiki описывает 134 типа триггеров, категории и особенности GD 2.2); часть страницы всё ещё дорабатывается.
- [GD2.2 Object IDs to plist file names](https://gist.github.com/frqubit/39bf5e3c6a072096424d93055991d7f8) — ID конкретных иконок/объектов и триггеров в EXE GD 2.2; найти название и затем проверить ID в 2.209.
- [GD Docs — level-string properties](https://boomlings.dev/resources/client/level-components/level-string) — поля строки объектов (`28` Move X, `51` target group и т. д.).
- [GDCreatorSchool — Using IDs](https://github.com/GDCreatorSchool/gdcs2/blob/main/content/docs/guides/the-editor/using-ids.md) — Group, Color, Effect, Block, Item/Time, Trigger Channel и другие ID. В самом руководстве предупреждение: часть материала ещё обновляется для 2.209.
- [GDCreatorSchool — Using Channels](https://github.com/GDCreatorSchool/gdcs2/blob/main/content/docs/guides/the-editor/using-channels.md) — порядок триггеров/каналов и изменение направления.
- [RobTop — Editor Guide](https://www.robtopgames.com/files/GDEditor.pdf) — официальный редактор и встроенные ограничения.

**Неизвестные числа не угадывать!** Если в таблице нет ID, агент должен найти его в полном индексе, создать минимальный уровень в игре, сверить объект, экспортировать и распарсить `k4`. Для новых 2.209-полей опираться на реальный экспорт, а не только на старые 2.1-таблицы.

## 3. Area/Enter-триггеры 2.2 и их ID

| ID | Тип | Что умеет |
| --- | --- | --- |
| `3006` | Area Move | двигать объекты в зоне вокруг цели |
| `3007` | Area Rotate | поворачивать объекты в зоне |
| `3008` | Area Scale | масштабировать объекты в зоне |
| `3009` | Area Fade | изменять прозрачность в зоне |
| `3010` | Area Tint | изменять окраску в зоне |
| `3011–3015` | Edit Area Move/Rotate/Scale/Fade/Tint | менять уже активные Area-эффекты |
| `3024` | Area Stop | останавливать эффекты зоны |
| `3017–3021` | Enter Move/Rotate/Scale/Fade/Tint | обрабатывать вход/приближение объектов |
| `3023` | Enter Stop | останавливать Enter-эффекты |
| `3022` | Teleport | перемещение к назначенной точке/группе |

Все перечисленные типы сейчас **RAW-only**. Area/Enter зависит от положения цели, её зоны, приоритетов, Effect/Enter Channel и настроек эффекта. Не применять в сложных местах без игрового теста.

## 4. Другие семейства триггеров: полный план возможностей

Названия перечислены для планирования и поиска по источникам. Для **не указанных** здесь ID и ключей конфигурации нужен отдельный экспорт/проверка; их нельзя считать готовым API.

### Группы, время, логика и события
- **Random / AdvRandom:** случайное ветвление и веса групп.
- **State / Collision State / Instant Collision:** проверка событий и состояний.
- **Touch / Pickup / Count / Instant Count / Item Edit / Item Compare / Item Persistence:** взаимодействия, счётчики, переменные, проверки условий, ветвления.
- **Time / Time Event / Time Control / Cooldown:** таймеры, задержки, ограничения повторного срабатывания.
- **Event Link / Sequence / Spawn / Stop / Toggle / Reset / On Death:** оркестрация групп, последовательности и реакции на действия.
- **Pause / Resume / Stop Jump / Player Control / End:** управление состоянием уровня/игрока.

### Визуальные эффекты и анимация
- **Color / Pulse / Alpha / Gradient:** цветовые каналы, свечения, прозрачность, градиентные области.
- **Move / Rotate / Scale / Follow / Follow Player Y / Advanced Follow:** движение и геометрические трансформации.
- **Keyframe / Animate / Particle / Spawn Particle:** сложная анимация и частицы.
- **Shake / Flash / UI / BG-MG Speed:** визуальные акценты, интерфейс и скорость фоновых слоёв.
- **Enter и Area:** эффекты с привязкой к камере, игроку, целевой группе или области.

### Камера 2.2
- **Zoom:** масштаб камеры.
- **Static:** фиксация на целевой группе, выход из Static.
- **Offset / Gameplay Offset:** смещение обзора и положения игрока в кадре.
- **Rotate:** поворот камеры.
- **Edge:** привязка границы камеры к группе.
- **Mode:** настройки свободной камеры/ограничений.
- **Guide:** контур видимой области в редакторе (не игровой эффект).

Каждому переходу камеры нужны время, easing и ограничение, чтобы игрок видел следующий участок и не терял ориентацию.

### Шейдеры/постобработка 2.2
- **Shader layer/effect range**, **Shock Wave**, **Shock Line**, **Glitch**, **Chromatic**, **Chromatic Glitch**, **Pixelate**, **Lens Circle**, **Radial Blur**, **Motion Blur**, **Bulge**, **Pinch**, **Gray Scale**, **Sepia**, **Invert Color**, **Hue**, **Edit Color**, **Split Screen**.
- Это именно **визуальные эффекты**. Не применять сильные Blur/Glitch/Flash поверх узких препятствий и без возможности отключить/уменьшить интенсивность.

### Музыка и звук
- **Song:** запуск/смена песни, включая song channel.
- **Edit Song:** громкость, скорость, остановка, область воспроизведения и др.
- **SFX / Edit SFX:** звуковые эффекты, pitch/volume/loop/proximity.
- **BPM:** вспомогательная сетка музыкальной разметки *в редакторе*; не гарантия синхронизации игровых объектов.
- **Song Channel / Unique ID / SFX Group ID:** независимое управление несколькими звуками.

### Изменение геймплея, платформер, уровень
- **TimeWarp:** скорость течения игрового времени.
- **Gameplay / Arrow / Reverse / ReverseDir / Gravity:** смена направления, гравитации, игровых каналов и направления продвижения.
- **BG/G/MG Switch:** смена фоновых слоёв и земли.
- **Options, End, Player Control, Start Pos, Reset:** конфигурация, завершение и управление сценой.
- **Teleport / Checkpoint / Force Blocks / Collision Blocks:** перенос игрока, контрольные точки, физические взаимодействия.
- **Keyframe**, **Event Link**, **UI** позволяют создать внутри редактора интерактивную сцену, а не только типичный auto-run.

## 5. Как работают ID, группы и каналы

**Object ID** (`1`) — тип конкретного блока/портала/триггера, **не** номер элемента. **Group ID** (`57`) — группа объектов, на которую нацеливаются триггеры. **Color Channel ID** (`21/22`) — основной/дополнительный цвет самого объекта; **Target Color ID** (`23`) — изменяемый канал у цветового триггера. **Target Group ID** (`51`) — адресат, например, Move/Alpha. Это разные пространства имён.

Другие системы ID: **Item ID / Time ID** (переменные), **Block ID** (Collision Blocks), **Effect ID** (Area/Enter), **Control ID**, **Song Channel**, **SFX Group/Unique ID**, **Gradient ID**, **Material ID**, **Force ID**, **Enter Channel**, **Trigger Channel**, **Animation ID**. **Номер не говорит о типе ID**: тип задаётся полем конкретного объекта/триггера.

- Group ID 2.2: до **9999** по руководствам; не допускать неосознанных пересечений, вести реестр в JSON blueprint.
- У одного объекта может быть несколько групп: строковое поле `57`, разделитель `.` (например `101.102`).
- Spawn Trigger запускает триггеры, не заменяет Toggle. Учитывать `Spawn Triggered`, `Touch Triggered`, `Multi Activate`, каналы и порядок исполнения.
- Editor Layer (`20`) только для организации редактора; Z Layer (`24`) и Z Order (`25`) задают видимый порядок.

### Поля `GDObject.props` (подтверждённое базовое подмножество)

| Key | Назначение | Частые пользователи |
| --- | --- | --- |
| `7/8/9` | RGB компоненты | Color |
| `10` | duration (в некоторых триггерах имеет иной смысл) | Color/Move/Alpha; **не универсально** |
| `11` | Touch Triggered | интерактивные триггеры |
| `17` | blending | часть цветовых объектов |
| `21/22` | Main/Secondary Color ID | визуальные объекты |
| `23` | Target Color ID | Color |
| `24/25` | Z Layer / Z Order | рисуемые объекты |
| `28/29` | Move X/Y | Move |
| `30` | easing | анимированные триггеры |
| `33/57` | single/multiple Group ID | объекты и trigger setup |
| `35` | opacity | Color/Alpha |
| `45/46/47` | fade-in / hold / fade-out | Pulse |
| `51` | target Group ID | Move/Rotate/Scale/Alpha/Toggle и др. |
| `62` | Spawn Triggered | триггеры, активируемые группой |
| `63` | Spawn Delay | отложенный spawn |
| `80` | Item / Block ID (зависит от типа) | счётчики/collision |
| `104` | Multi Activate у триггера | повторные события |

Многие свойства имеют **контекстно-зависимую семантику**, enum, кодировку, вторичные поля и условные зависимости. Таблица не является полной схемой GD 2.209. Перед реализацией проверять [GD Docs](https://boomlings.dev/resources/client/level-components/level-string) и экспорт из игры.

## 6. Примеры с явно существующими полями

```python
from gdgen.objects import GDObject, make_color_trigger

# Объект в группе 101.
object_to_move = GDObject(1, 600, 225, {21: 1, 57: "101"})

# Move на 30 units вправо за 0.8 с.
# Демонстрирует базовые ключи, а НЕ гарантирует безопасное поведение в игре.
move = GDObject(901, 540, 15, {51: 101, 28: 30, 29: 0, 10: 0.8})

# Цветовой триггер — единственный из примеров, для которого в проекте
# уже есть готовый helper и применение в генераторе.
color = make_color_trigger(720, channel=1, rgb=(20, 240, 255), duration=1.5)

# Alpha для группы 101: затухание до 0.5 за 1 с.
alpha = GDObject(1007, 750, 15, {51: 101, 35: 0.5, 10: 1.0})
```

**Важно:** для Moving solid block в реальном уровне нужны прогнозируемые коллизии и безопасные окна реакции. Без этого `validate()` пропустит потенциально непроходимую секцию.

## 7. Контрольная карта внедрения новых типов

1. Найти точный ID/назначение и экспортировать образец 2.209.
2. Установить обязательные свойства, типы, диапазоны, значения по умолчанию и зависимость от группы/канала.
3. Добавить high-level helper или typed config, а не повсюду писать магические числа.
4. Добавить реестр занятых Group/Item/Effect/Color ID и отдельные подсистемы для триггеров и порядка событий.
5. Написать round-trip тест, валидатор ссылок и проверку безопасности с коллизиями.
6. Обновить PNG-предпросмотр (статический рисунок анимацию не показывает), добавить таймлайн или ключевые кадры.
7. Проверить триггер внутри Geometry Dash и только после этого обозначить как ENGINE.

**В ближайшем этапе:** сначала уменьшить сложность маршрутов (Neon Cyber City слишком сложен), затем реализовать Move/Pulse/Alpha/Spawn/Toggle/Scale для **чисто декоративных групп**, позже — камеру, шейдеры и физические триггеры. Статический валидатор пока не гарантирует проходимость динамических препятствий.

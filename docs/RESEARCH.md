## 2. GD AI Bridge (RibomX/GD-AI-bridge)

Изучен README, `mcp/offline.js` и структура проекта (MIT).

Что даёт проект:

- Geode-мод, поднимающий HTTP API на `127.0.0.1:7312` для живого редактирования
  уровня в редакторе, playtest и чтения объектов;
- **offline-режим** в MCP-адаптере на Node.js: правит `CCLocalLevels.dat`
  напрямую при закрытой игре, делает бэкапы;
- экспорт `.gdlvl` — «plist dict уровня, gzip + url-safe base64»;
- готовые измеренные константы физики (высота/длина прыжка, ship, пады, орбы).

Почему MCP-сервер не используется напрямую:

1. **Node.js не установлен**, а MCP-адаптер существует только как npm-пакет.
2. **Geode-мод несовместим с GD 2.209+** — автор прямо предупреждает, что мод
   может уронить игру или повредить уровень; поддержка ждёт Geode v6.
3. Живое редактирование и playtest на установленной версии недоступны.
4. Ставить сторонний мод и Node.js только ради offline-режима избыточно:
   тот же формат можно реализовать на Python без зависимостей.

Что взято из проекта:

- точная схема кодирования сохранения: `XOR 11 → url-safe base64 → gzip → XML plist`;
- схема `.gdlvl`: `gzip(XML plist) → url-safe base64` (без XOR);
- список ключей уровня, которые GD пишет при экспорте;
- измеренная физика и рекомендации по координатам;
- подход к безопасности: проверка запущенной игры, бэкап, запись во временный
  файл с проверкой чтения.

## 3. Формат `.gdlvl` и способы импорта

`.gdlvl` — это неофициальный контейнер, который GD 2.209+ понимает штатной
кнопкой **Import**:

```
.gdlvl  = urlsafe_base64( gzip( XML plist с одним <dict> уровня ) )
```

Внутри dict ключевое поле `k4` — строка уровня, которая сама может быть
`urlsafe_base64(gzip(level string))`.

Проверенные варианты импорта:

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| Штатный Import в GD 2.209+ | Без модов, игра сама валидирует и создаёт уровень, работает даже при запущенной игре | Нужен клик в UI | **Основной** |
| Правка `CCLocalLevels.dat` offline | Полностью автоматизируется | Нужен закрытый Steam Cloud, риск при неверном формате | Дополнительный, с бэкапом |
| Geode + GD AI Bridge | Живое редактирование, playtest | Не поддерживает 2.209, нужен Node.js | Отклонён |
| Публикация в онлайн | — | Нарушает требования безопасности | Не используется |

## 4. Формат строки уровня

Изучен на реальном `.gmd` (локальный справочный файл, в репозиторий не
попадает) и на открытых парсерах (`GDParse`, `gdparse`). Подробности — в
[FORMAT.md](FORMAT.md).

Ключевые выводы:

- 1 блок = 30 units, центры клеток: 15, 45, 75, …; `y=15` — первый ряд над землёй.
- объект: `1,<id>,2,<x>,3,<y>,<prop>,<value>,…;`
- заголовок уровня содержит `kS38` (цветовые каналы), `kA6` (фон), `kA7` (земля),
  `kA4` (скорость) и другие настройки; заканчивается `;`.
- цвета: канал `1000` — фон, `1001` — земля, `1004` — объекты, `1..999` —
  пользовательские каналы; свойства канала `1/2/3` = RGB, `6` = id канала,
  `7` = alpha, `5` = blending.
- цветовой триггер `899`: `7/8/9` = RGB, `10` = длительность, `23` = канал,
  `35` = alpha.

## 5. Безопасность работы с сохранениями

- Перед любой записью — резервная копия `CCLocalLevels.dat.backup-<timestamp>`.
- Проверка `GeometryDash.exe` через `tasklist`; при запущенной игре запись
  запрещена.
- Запись в `*.tmp`, обратное чтение и распаковка, затем атомарная замена.
- Существующие уровни не удаляются и не переупорядочиваются без необходимости.
- Steam Cloud: документирован риск перезаписи; рекомендуемый путь — штатный
  Import, который не трогает файл сохранения вручную.
- Уровни не публикуются в игровую сеть.

## 6. Принятое решение

Реализовать собственный генератор и формат на Python (stdlib), с двумя каналами
импорта:

1. **основной** — `.gdlvl` + штатная кнопка Import (GD 2.209+);
2. **автоматический** — offline-добавление в `CCLocalLevels.dat` с бэкапом.

Это даёт работу без модов и Node.js, сохраняет совместимость с редактором
(уровень создаётся игрой либо как обычная запись локального уровня) и не
зависит от несовместимого с 2.209 Geode-мода.
